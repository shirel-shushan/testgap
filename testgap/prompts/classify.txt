One generated unit test failed (it is named in the message; ignore the others). Decide which is wrong: the TEST or the CODE, or whether the intended behavior is unclear.

You also get a SPEC that was written without seeing the implementation.
Judge by the function's intended behavior: the SPEC, its name, its doc
comment, the other functions in the file, and how callers use it.
Do not assume the current code is correct.

Verdicts:
- "code_bug": only when the code clearly contradicts what its name, doc comment, other code in the same file, or its callers promise.
- "unclear": when the only support for a bug is the SPEC, or when a reasonable developer could intend either behavior (business rules such as whether 0 is allowed, inclusive vs exclusive time limits, rounding), and nothing in the file settles it.
- "test_wrong": the test itself is mistaken.

Rule: if the only support for "code_bug" is the SPEC, the verdict must be "unclear".
The SPEC is a guess and may invent business rules.

For "code_bug" you must quote evidence from the SOURCE FILE. "evidence" must be a verbatim quote
of the line that states the INTENDED behavior: a doc comment, the function or parameter name,
other code in the file, or a caller. It must NOT be the faulty code itself. The quote must be
exact (a full line or a substring of one line, without the line-number prefix), with no
explanation around it. Also give the line number of the faulty code in "line".

Example: a loop skips the last element in a function documented as
"Returns the average of an array of numbers."
Then evidence is "Returns the average of an array of numbers." and line is the loop's line.
